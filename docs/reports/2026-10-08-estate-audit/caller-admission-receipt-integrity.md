## Repair map

1. **A11oy receipt sink — producer admission and content binding.** [`serve.py` registers the sink](https://github.com/szl-holdings/a11oy/blob/7afce7810c52bf9f5fd6d66afb56308d60b78a09/serve.py#L15826-L15846). The [POST handler](https://github.com/szl-holdings/a11oy/blob/7afce7810c52bf9f5fd6d66afb56308d60b78a09/szl_lake_ingest.py#L226-L242) appends and mirrors caller JSON without an in-handler producer check. [Store append](https://github.com/szl-holdings/a11oy/blob/7afce7810c52bf9f5fd6d66afb56308d60b78a09/szl_lake_store.py#L234-L281) accepts any dict and hashes caller organ, identity, timestamp and chain index, rather than always binding canonical nested receipt bytes; [rebuild](https://github.com/szl-holdings/a11oy/blob/7afce7810c52bf9f5fd6d66afb56308d60b78a09/szl_lake_store.py#L200-L224) trusts stored chain fields. Authenticate and authorize each producer and organ before append/mirror; validate receipt schema/signature claims; bind a canonical receipt digest into the chain and verify on restart. Regressions: missing/wrong credential, organ spoof, invalid signature, reused ID with altered body, stored tamper after restart, and batch mirror consistency. External edge controls were not reviewed.
2. **Ayllu Counsel Human Lock — caller assertion.** The [route](https://github.com/szl-holdings/ayllu/blob/790405e7f7ae7ba4807ba09613e122357edcbbfc/app.py#L343-L366) converts request JSON `human_lock` to a boolean and takes `prev_hash` from the same request. [Policy](https://github.com/szl-holdings/ayllu/blob/790405e7f7ae7ba4807ba09613e122357edcbbfc/ayllu/counsel.py#L157-L172) admits listed high-risk actions when that boolean is true. [Receipt minting](https://github.com/szl-holdings/ayllu/blob/790405e7f7ae7ba4807ba09613e122357edcbbfc/ayllu/counsel.py#L396-L427) uses any 64-character caller predecessor. Require server-verified, action-bound, expiring two-person approval; derive predecessor from an authoritative chain or label it caller-linked. Regressions: forged true/truthy string, missing approver, wrong action, replay, forked predecessor. The [current test](https://github.com/szl-holdings/ayllu/blob/790405e7f7ae7ba4807ba09613e122357edcbbfc/tests/test_counsel.py#L26-L38) covers a false lock only. This is informational generation; no filing or external legal action was observed.
3. **Immune inference seal — answer not bound and seal result unchecked.** [`infer.ts`](https://github.com/szl-holdings/immune/blob/d7ef52b3833ff5663db0885a81cf81775623cc27/server/routes/immune/infer.ts#L28-L82) preflights then returns an answer based on the NEMO verdict. The [second seal](https://github.com/szl-holdings/immune/blob/d7ef52b3833ff5663db0885a81cf81775623cc27/server/routes/immune/infer-answer.ts#L119-L135) records verdict flags/provider but omits exact answer digest and model, and does not require `sealed.pass` or a non-null receipt. [Cycle](https://github.com/szl-holdings/immune/blob/d7ef52b3833ff5663db0885a81cf81775623cc27/server/routes/immune/cycle.ts#L111-L168) can return `pass=false` and null receipt. Require an admitted seal and receipt before returning text; bind its exact digest and authorship metadata. Regressions: seal denial, deadman, append failure, null receipt, changed text, local fallback. The [test stub](https://github.com/szl-holdings/immune/blob/d7ef52b3833ff5663db0885a81cf81775623cc27/tests/immune-infer-provenance.test.ts#L51-L60) accepts `pass=true` with null receipt. The existing [readiness contract does check ledger integrity](https://github.com/szl-holdings/immune/blob/d7ef52b3833ff5663db0885a81cf81775623cc27/server/readiness.ts#L288-L332).
4. **SZL Energy Attest — signature downgrade in verifier.** [`_verify_signature`](https://github.com/szl-holdings/szl-energy-attest/blob/7823d106a8ecf056fa735af405cb658829a3f309/szl_energy_attest/meter_proxy/verifier.py#L48-L67) trusts editable `signature_present=false`, or `envelope.signed=false`, to classify a signature as absent/unsigned even after verification failure. [Overall state](https://github.com/szl-holdings/szl-energy-attest/blob/7823d106a8ecf056fa735af405cb658829a3f309/szl_energy_attest/meter_proxy/verifier.py#L70-L132) can remain `VERIFIED`; [signature fields are siblings of the hashed body](https://github.com/szl-holdings/szl-energy-attest/blob/7823d106a8ecf056fa735af405cb658829a3f309/szl_energy_attest/meter_proxy/receipts.py#L140-L157). Reject contradictory envelope states and enforce a trusted signer/key when signed attestation is required; preserve a distinct unsigned integrity-only result. Regressions: removed/invalid signature, false flag, wrong key, honest keyless mode. Separately, [sequence/predecessor are derived per issuer](https://github.com/szl-holdings/szl-energy-attest/blob/7823d106a8ecf056fa735af405cb658829a3f309/szl_energy_attest/meter_proxy/receipts.py#L83-L90) while [file lock covers append only](https://github.com/szl-holdings/szl-energy-attest/blob/7823d106a8ecf056fa735af405cb658829a3f309/szl_energy_attest/meter_proxy/receipts.py#L113-L169), so test two instances sharing a store. [Rollup verification](https://github.com/szl-holdings/szl-energy-attest/blob/7823d106a8ecf056fa735af405cb658829a3f309/szl_energy_attest/meter_proxy/verifier.py#L134-L157) should recompute day coverage and totals rather than only check that named digests exist.
