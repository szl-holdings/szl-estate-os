## 0. Design decisions (proposal)

| Decision | Choice | Why (doc basis) |
|---|---|---|
| Runtime | **Warehouse runtime** (default when RUNTIME_NAME is omitted) | On-demand. Sleep timer supported. Container runtime bills a compute pool continuously and keeps running until 3 days of viewer inactivity. |
| Compute | One dedicated **X-Small** warehouse `SZL_EE_WH`, single cluster, used as the app's code + query warehouse | XS = 1 credit/h. Snowflake recommends a dedicated Streamlit warehouse for cost isolation. |
| Spend control | Dedicated resource monitor `SZL_EE_RM` assigned **only** to that warehouse, plus AUTO_SUSPEND=60, STATEMENT_TIMEOUT_IN_SECONDS, and **AUTO_RESUME=FALSE outside approved windows** | Docs: one warehouse per monitor; monitors are not precise caps. |
| Data | Deterministic **synthetic** fixture only; the label "SYNTHETIC DEMONSTRATION DATA — NOT PRODUCTION OR MODEL QUALIFICATION." appears in data and UI | Mission §5 |
| Schema | `SZL_EE_DB.EE_DATA` and `SZL_EE_DB.EE_APP`, both **WITH MANAGED ACCESS**; DATA_RETENTION_TIME_IN_DAYS = 1 | Prior review finding 4b.4 |
| Ownership | No pilot object is owned by ACCOUNTADMIN. ACCOUNTADMIN is used **only** to create and assign the resource monitor (docs: only ACCOUNTADMIN can create one). | Prior review finding 4b.3 |
| Audience | Private, view-only, one named reviewer role. Initially only Stephen's own user. | Mission §5 |
| Not used | Cortex/AI, external access integrations, Git API integration, embedding, service users, secrets, network-policy changes, tasks, Snowpipe, compute pools, budgets objects (see COST_AND_SHUTDOWN §5) | Mission §5. Docs: trials lack external access, and AI is off by default. |
| Tenancy | **Single-tenant** pilot. No isolation claim is made. | Mission §8 |

## 2. Rollback procedure (never deletes data without approval)

The following are **safety actions** that Stephen may pre-approve as always allowed (AP-G1). None of them deletes data.
1. `ALTER WAREHOUSE SZL_EE_WH SUSPEND;` and `ALTER WAREHOUSE SZL_EE_WH SET AUTO_RESUME = FALSE;`
2. Revoke viewer access: `REVOKE USAGE ON STREAMLIT SZL_EE_DB.EE_APP.SZL_EVIDENCE_EXPLORER FROM ROLE SZL_EE_VIEWER;` and `REVOKE ROLE SZL_EE_VIEWER FROM USER <user>;`
3. Stop writes: `REVOKE INSERT ON ALL TABLES IN SCHEMA SZL_EE_DB.EE_DATA FROM ROLE SZL_EE_INGEST;` This is an explicit revoke on named objects; no FUTURE grants exist.
4. Tighten the monitor: `ALTER RESOURCE MONITOR SZL_EE_RM SET CREDIT_QUOTA = <used>;` This needs ACCOUNTADMIN, so it falls under AP-C1.

The following need **separate, explicit approval** (AP-G2), naming the exact objects:
- DROP of any Streamlit, stage, table, schema, database, warehouse, monitor or role;
- TRUNCATE/DELETE;
- any CREATE OR REPLACE over an existing object.

Note:
- Dropped objects can sometimes be recovered with UNDROP inside the retention window, but this plan does **not** rely on that.
- Ingestion batches and exclusion records are never deleted for a rerun (mission §6).
- An app bug is fixed by uploading `v2/` and running `ALTER STREAMLIT … SET` / re-creation under AP-F2. Data is not reset.

Rollback verification:
- `SHOW WAREHOUSES LIKE 'SZL_EE_WH';` shows SUSPENDED and auto_resume false.
- `SHOW GRANTS ON STREAMLIT …;` shows the owner only.
- `SHOW GRANTS TO ROLE SZL_EE_INGEST;` shows no INSERT.
